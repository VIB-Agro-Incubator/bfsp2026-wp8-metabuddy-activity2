MetaBuddy Assistant API — Conversational (0.4.0)

Download OpenAPI specification:

LLM-powered ISA metadata assistance API, consumed by ISA Wizard. This is the conversational specification. It is an independent alternative to the minimal specification, targeting /api/v2. It adds:

  • Sessions — persistent context and conversation history across a full wizard run, allowing MetaBuddy to give richer, continuity-aware responses.
  • Chat — a freeform conversational endpoint not tied to a specific ISA field, for open questions within the current wizard scope.
  • Asynchronous responses — a job polling pattern for long-running operations (primarily file conversion), returning immediately with a job ID and allowing ISA Wizard to poll for the result.

Relationship to the Minimal spec

This specification is independent of the minimal spec. Both versions run simultaneously on the server — /api/v1 (minimal, stateless) and /api/v2 (conversational, session-aware) coexist and do not interfere with each other. The client application decides which version to target based on its own development state; different client branches may support different versions. The stateless /convert, /validate, /explain endpoints from the minimal spec are not present here; all assist calls in this spec are session-scoped.

Authentication

ISA Wizard authenticates as a service client using a pre-shared API key (X-API-Key header) issued by MetaBuddy. This is a backend-to-backend credential managed via a Keycloak service account on the MetaBuddy side. Individual end-user identity does not cross the boundary. ISA Wizard end-users may be anonymous.

Session lifecycle

  1. ISA Wizard calls POST /sessions at the start of a wizard run.

  2. As the user advances through wizard steps, ISA Wizard calls PUT /sessions/{sessionId}/context to push the updated ISA-JSON.

  3. Assist calls reference the session by sessionId; no need to re-send full context on every call.

  4. ISA Wizard calls DELETE /sessions/{sessionId} when the wizard run is completed or abandoned. Sessions also expire automatically on the server side after a period of inactivity; the TTL is an implementation detail for the MetaBuddy team to determine.

Streaming

SSE streaming support for the /chat endpoint is pending. When implemented, clients will be able to request token-by-token responses by sending Accept: text/event-stream, producing a typing effect in the UI.

Async job pattern

Endpoints that support async return 202 Accepted with a jobId. ISA Wizard polls GET /jobs/{jobId} until status is completed or failed.

Jobs

Poll for results of async operations. Used when ISA Wizard passes the 'Prefer: respond-async' header to a supported endpoint.

Poll for async job result

Returns the current status and, once completed, the result of an async job. ISA Wizard should poll this endpoint after receiving a 202 response from any endpoint that supports async operation. Suggested polling interval: 2–5 seconds.

Assist

Session-scoped assist calls: file conversion, validation, field explanation, and freeform chat. All calls are informed by session context and history.

Convert uploaded files to ISA-JSON (session-aware, async supported)

File-to-ISA conversion using the session's stored context and history. MetaBuddy merges extracted information into the session's current ISA-JSON rather than generating from scratch. Supports async operation: pass prefer: respond-async in the request header to receive a 202 with a jobId instead of waiting for the full result. Recommended for large file uploads.

Freeform chat within session context

Open-ended conversational endpoint for questions not tied to a specific ISA field. Uses the session's full stored context (ISA-JSON state + conversation history) to give contextually relevant answers. Examples of appropriate chat messages: - "I'm not sure if my experiment is an intervention or observational study." - "Can you summarise what we've defined so far for this study?" - "What's the difference between a study factor and a study characteristic?" The response includes relatedFields so ISA Wizard can optionally highlight or navigate to the fields mentioned in the answer. SSE streaming support is pending. When available, send Accept: text/event-stream to receive tokens incrementally.
