MetaBuddy Assistant API — Minimal (0.2.1)

Download OpenAPI specification:

LLM-powered ISA metadata assistance API, consumed by ISA Wizard. This is the minimal specification. All calls are synchronous and stateless — ISA Wizard owns all state and passes the relevant ISA-JSON context on every request. No session management is required.

Authentication

ISA Wizard authenticates as a service client using a pre-shared API key (X-API-Key header) issued by MetaBuddy. This is a backend-to-backend credential managed via a Keycloak service account on the MetaBuddy side. Individual end-user identity does not cross the boundary. ISA Wizard end-users may be anonymous.

Scoping

Every endpoint accepts a scope parameter that indicates which ISA hierarchy level the user is currently at in the wizard.

Assist

Stateless assist calls: file-to-ISA conversion, ISA-JSON validation, and contextual field explanation. Each call is fully self-contained.

Convert uploaded files to ISA-JSON

The user uploads one or more files they consider relevant (lab notebooks, metadata spreadsheets, protocols, README files). MetaBuddy extracts and maps content to the ISA schema at the given scope level, returning a partial or complete ISA-JSON. If existingIsa is supplied, MetaBuddy merges extracted information into the existing structure rather than generating from scratch. Suggested supported file types: PDF, XLSX, CSV, DOCX, TXT. Maximum file size per upload to be agreed with the MetaBuddy team.

Authorizations:
ApiKeyAuth
Request Body schema: multipart/form-data
required
scope
required
string (IsaScope)
Enum: "investigation" "study" "assay"

ISA hierarchy level the user is currently at in the wizard. Must be one of: investigation, study, or assay (all lowercase). Maps directly to the three levels of the ISA standard. MetaBuddy uses this to limit its response to what is relevant at that level.

existingIsa
string

JSON string of existing ISA-JSON to extend (optional). MetaBuddy will fill gaps rather than overwrite existing values.

Validate ISA-JSON at a given scope level

Checks the provided ISA-JSON for completeness and correctness within the given scope. Combines rule-based checks (required fields, controlled vocabulary) with LLM-generated contextual suggestions. Errors indicate missing required fields or invalid values. Warnings indicate potential issues. Suggestions are optional improvements.

Explain an ISA field or answer a user question

Returns a contextual explanation of a specific ISA field, optionally answering a freeform user question typed in the ISA Wizard UI. The current ISA-JSON state should be passed as isaJson so that MetaBuddy can tailor the explanation — for example, recommending ontology terms relevant to the organism or experiment type already recorded. If field is an empty string and userQuestion is provided, this acts as general freeform Q&A scoped to the current ISA level.

ApiKeyAuth
Request Body schema: application/json

required

userQuestion
string

Optional freeform question from the user. If omitted, MetaBuddy returns a generic explanation of the field.
